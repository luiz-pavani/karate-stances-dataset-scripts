# Kinetic time-series — per-trial raw export

192 CSV files (180 dynamic + 12 STATIC) of unprocessed force-platform
records exported by the Qualisys QTM acquisition system from two
Bertec FP4060-15 force platforms sampled at 1000 Hz.

Generated by `python -m kds.export_kinetic_timeseries` from the source
TSV files at `DATASET/Kinetic/`. **No filtering, no platform combination,
no descriptor extraction was applied.** Force, moment, and centre of
pressure are released exactly as exported by QTM in the laboratory frame.

## Layout

```
timeseries_kinetic_raw/
├── <ID>_<BASE>_T<N>_kinetics.csv         dynamic trials (180 files)
├── static/
│   └── <ID>_STATIC_T1_kinetics.csv       STATIC references (12 files)
├── kinetic_qc_report.csv                 per-trial QC flags
└── kinetic_plate_corners.csv             4 corners of each plate per trial
```

The `ID009/KUK` acquisition-time typo is resolved at load time and the
corresponding files are written as `ID009_KOK_T<N>_kinetics.csv`.

## Schema — `<ID>_<BASE>_T<N>_kinetics.csv`

Each trial CSV carries **20 columns**: 2 identifying columns and a
side-by-side 9-column block for each of the two force platforms (Bertec
3 = front foot, Bertec 4 = rear foot in `ZEN`/`KOK`; arbitrary left/right
assignment for the symmetric `KIB`). For trials in which only one
platform fired (5 trials documented in the QC report), the columns of
the absent platform are filled with `NaN` to preserve the dataset's
matrix-shape regularity.

Dynamic trials are 9 000 rows × 20 columns (9.00 s at 1000 Hz, with rare
exceptions documented in the QC report). STATIC references are shorter
(typically ~1 000–2 000 samples).

| Column | Variable | Unit | Frame |
|---|---|---|---|
| `frame` | sample index 0 … N−1 | — | — |
| `time_s` | time since trial start | s | — |
| `FP3_Fx_N`, `FP3_Fy_N`, `FP3_Fz_N` | ground reaction force, Bertec 3 | N | lab |
| `FP3_Mx_Nmm`, `FP3_My_Nmm`, `FP3_Mz_Nmm` | free moments about the plate centre, Bertec 3 | N·mm | plate |
| `FP3_COPx_mm`, `FP3_COPy_mm`, `FP3_COPz_mm` | centre of pressure, Bertec 3 | mm | lab |
| `FP4_Fx_N`, `FP4_Fy_N`, `FP4_Fz_N` | ground reaction force, Bertec 4 | N | lab |
| `FP4_Mx_Nmm`, `FP4_My_Nmm`, `FP4_Mz_Nmm` | free moments, Bertec 4 | N·mm | plate |
| `FP4_COPx_mm`, `FP4_COPy_mm`, `FP4_COPz_mm` | centre of pressure, Bertec 4 | mm | lab |

### Sign convention

The Qualisys export expresses forces and centres of pressure in the
**laboratory** coordinate frame: X mediolateral, Y anteroposterior, Z
vertical (upward positive). A standing participant therefore produces a
**negative `Fz`** (the platform sees a downward reaction force). The
moment vector is the **free moment** of the centre of pressure about the
plate's geometric centre — i.e. *not* the full moment vector at the
plate's origin. Consult `kinetic_plate_corners.csv` for the precise
laboratory-frame position of each plate's corners.

### Sampling

The native acquisition rate is **1000 Hz**. The companion kinematic
stream (Theia3D markerless reconstruction) is sampled at **180 Hz** in
the same laboratory frame; the two are synchronised at acquisition time
by the Qualisys QTM hardware trigger and share a common `time_s = 0`
origin. **No resampling is performed in the released CSVs**: kinetic
data are at 1000 Hz, kinematic data at 180 Hz. Users requiring a common
time base are free to interpolate either stream onto the other.

## Schema — `kinetic_qc_report.csv`

One row per trial (192 rows). Columns:

| Column | Description |
|---|---|
| `subject` | participant code (`ID003`–`ID014`) |
| `base` | postural base (`ZEN` / `KOK` / `KIB` / `STATIC`) |
| `trial` | repetition index (1..5 for dynamic; 1 for STATIC) |
| `n_samples` | number of samples actually acquired |
| `rate_hz` | acquisition rate (1000.0) |
| `duration_s` | trial duration |
| `has_plate_3`, `has_plate_4` | True/False, whether each plate fired |
| `n_plates` | 1 or 2 |
| `source_path_3`, `source_path_4` | original TSV path |
| `kuk_alias_applied` | True if the source path contained the `KUK` typo and was mapped to `KOK` |

**Five trials are documented with only one platform fired** (the other
plate either had a foot only marginally on it or had no contact at
all). These trials are retained in the released dataset for completeness
and transparency; users are free to exclude them based on their
analytical needs.

## Schema — `kinetic_plate_corners.csv`

One row per (trial, plate, corner). Columns: `subject`, `base`, `trial`,
`plate` (3 or 4), `corner` (one of `POSX_POSY`, `NEGX_POSY`, `NEGX_NEGY`,
`POSX_NEGY`), `x_mm`, `y_mm`, `z_mm`. The corner positions allow users
to verify the plate geometry against the laboratory frame for every
acquired trial.

## Source-file variants

The source TSV files come in two export variants, transparently handled
by the loader (`kds.loader_kinetic`):

- **11-column variant** (subjects `ID003`, `ID004`): `sample_index, time,
  Fx, Fy, Fz, Mx, My, Mz, COPx, COPy, COPz` with trailing tab.
- **9-column variant** (subjects `ID005`–`ID014`): `Fx, Fy, Fz, Mx, My,
  Mz, COPx, COPy, COPz` — sample index and time are reconstructed at
  load time from the `NO_OF_SAMPLES` and `FREQUENCY` header fields.

Both variants produce **identical column ordering and naming in the
released CSVs**; the released files are therefore format-uniform across
the cohort.

## What is *not* in these CSVs

- No filtering, no platform combination, no force-weighted resultant
  COP.
- No descriptors (load percentages, sway, MoS, RSR). Those will be
  computed by users from the released raw streams.
- No demographic metadata.
- No kinematic data — see `data/timeseries_raw/` for the matched per-trial
  kinematic CSVs.

## Regeneration

```bash
python -m kds.export_kinetic_timeseries \
    --data-root "/path/to/Kinetic" \
    --output-dir ./data/timeseries_kinetic_raw
```
